# DSH Super-Agent 任务书：Costume Director Knowledge System

## 0. 任务定义与执行边界
你是项目负责人兼系统架构师，目标是交付可由 Obsidian 直接打开、可被 AI 检索调用的影视服装研究与角色造型知识库，而不是仅生成几份介绍文字。知识库面向人物生图、视频提示词、角色设计、剧本服装设计与镜头连续性。

- 目标项目目录：当前目录 `Costume-Director-Vault-Starter/`；必须先核实绝对路径、沙箱写权限和已有文件，不要误写到其他仓库、其他 Obsidian Vault。
- 输出格式：本地 Markdown + 扁平 YAML frontmatter + Obsidian `[[wikilinks]]`；优先标准格式，最初不依赖第三方 Obsidian 插件。
- 运行环境：DeepSeek Harness；Super-Agent 仅负责 Router/Worker 调度。模型上下文不等于知识库，全部成果必须落盘、可重复读取。
- 网络：仅从合法公开资料收集；若网络不可用，不伪造检索事实。单独记录 `BLOCKED` 并完成离线结构与示例。
- 自主执行：允许创建项目内文件、索引和测试脚本；不得删除或覆盖既有用户资产、不得运行未知来源安装脚本、不得上传私人剧本或本地文件到第三方服务、不得公开发布仓库或自动合并 PR。任何涉及凭据、付费服务、侵入性抓取、危险命令的操作需用户明确确认。
- 若有多个 Worker，按来源研究、语义分类、场景匹配和 QA 并行，每个 Worker 仅写自己的 staging 区，由集成 Worker 校验后合并，避免互相覆盖。

## 1. 产品能力（必须实现）
1. **服装本体（ontology）**：区分单品类别、局部结构、材质属性、风格、年代文化、使用场景；不能把“西装”“极简主义”“丝绸”“1930年代”放成同一层级。
2. **剧情服装分析**：从剧本提取人物、剧情日、时间地点、阶层职业、人物关系、行动/气候/美术与摄影约束、角色变化；缺项标注 `unknown`，不得自行断言。
3. **造型推荐**：结合硬条件先过滤，再以可解释评分给出不少于 3 套候选 Look；每一套必须能拆解为上装、下装/连身、外层、鞋、配饰等具体单品和属性。
4. **提示词生成**：输出中文造型设计说明、英文人物生图提示词、英文视频提示词、角色一致性锁定字段（服装 ID、颜色材质、配饰位置、前后镜头状态），附负向约束。
5. **知识检索接口**：在本项目内创建可被 DSH 读文件或调用的检索入口。V0 采用 Python 标准库的文本/字段检索即可；后续可升级 SQLite FTS5 / embedding / MCP，但不得把网络向量库作为打开 Obsidian 的前提。
6. **溯源/许可**：每条历史、文化、工艺事实必须追溯来源。所有外部图片记录权利声明与原始链接；未确认许可的图片只存链接，禁止批量下载后嵌入 Vault。

## 2. 分类架构
### A 物理单品 (GARMENT)
- 上装：衬衫、T 恤、针织、毛衣、背心、马甲、束身衣等。
- 下装：长裤、短裤、半裙、裤裙、特殊下装。
- 连身：连衣裙、连体裤、连身工作服、长袍等。
- 外层：西装外套、夹克、大衣、风衣、斗篷、披风。
- 内层：衬衣/衬裙、打底层、功能性贴身衣物。
- 足部：鞋靴、袜、绑腿。
- 可穿戴配饰：帽/头饰、眼镜、围巾、手套、领带、腰带、首饰、胸针、腕部物。
- 携带与表演关联物：包袋、伞、手杖、随身物（作为 `carried_prop`，不要混同为服装本体）。
- 专门类型：制服、防护装备、戏曲/舞台装束、传统地域服装；按真实文化名称单独研究，支持跨类别映射，杜绝一概归类为“民族风”。
### B 构造和形态 (PART / CONSTRUCTION)
领型/领口、肩线、袖型、门襟、口袋、腰线、裤型、褶裥、衩、缝线、装饰、闭合方式、长度、层搭关系。
### C 属性 (ATTRIBUTE)
廓形、合体度、版型比例、材料/织造、重量、垂坠/挺括、反光/透明/弹性、色系/色值、图案/纹样、表面磨损/新旧、运动时动态表现、布光反应。
### D 风格 (STYLE)
必须用多对多标签区分：历史风格、艺术/视觉风格、社群亚文化、职业制服、电影类型造型、虚构世界观；风格不可替代具体单品记录。
### E 时空与剧情 (CONTEXT)
年代、地域/气候/季节、礼仪、职业/阶层/经济状况、身份与角色目标、戏剧冲突与人物弧线、场景行为、摄影布光、制作预算。
### F Look 及场次连续性 (LOOK / CONTINUITY)
Look = 一套具体搭配，拥有 Look ID；Scene-look = 角色、剧本场次、剧情日、镜头顺序和服装状态映射，记录破损、污渍、湿度、纽扣与配饰状态。

## 3. 每条卡片的最小字段（YAML 禁止嵌套，兼容 Obsidian Properties）
`id`, `type`, `name_zh`, `name_en`, `category`, `subcategory`, `aliases`, `periods`, `regions`, `style_tags`, `colors`, `materials`, `source_ids`, `evidence_status`, `license_status`, `review_status`, `tags`。
- 所有字段按数据字典的类型检查，列表用 YAML 数组，未识别时间与地域用空列表或明确 unknown；不使用伪精确年代。
- 对具体单品加 `silhouette`, `fit`, `season`, `formality`, `movement_notes`, `lighting_notes`, `prompt_en`。
- 对来源卡加 `url`, `publisher`, `date_accessed`, `rights_statement`, `source_kind`。
- 正文必须含：定义、结构要点、视觉辨识、适用条件、不适用条件、提示词短语、来源链接、相关卡片。
- 原创设计推断与有历史资料佐证的事实必须明确分开。

## 4. 资料来源优先顺序
1. Fashionpedia 专家本体（类目与属性参考）：https://fashionpedia.github.io/home/index.html
2. Getty Art & Architecture Thesaurus（标准术语）：https://www.getty.edu/research/tools/vocabularies/aat/
3. FIT Fashion History Timeline（年代、辞典、对象研究）：https://fashionhistory.fitnyc.edu/
4. The Met Open Access（馆藏与图像授权核验）：https://github.com/metmuseum/openaccess
5. Costume Designers Guild（剧本、角色与服装设计）：https://costumedesignersguild.com/what-is-costume-design/
6. Screen Ireland Costume Department 能力框架（script breakdown / continuity）：https://www.screenireland.ie/images/uploads/general/Booklet_5_-_Costume_Department_2024.pdf
7. 其他博物馆、学术论文、出版机构与实物馆藏：逐条记录可核验来源及许可。
严禁把营销文案、无来源的 Pinterest 图片、自动生成页面当作历史权威；不得假称图像、论文或博物馆信息已核实。

## 5. 分阶段执行（默认无需逐步询问）
**P0 — 架构与可运行性：** 完成目录、数据字典、模板、许可规范、Source Register、基础搜索工具、最小测试与 5 张真实或明确标注“原创示例”的卡片。报告全部实际文件与测试输出。

**P1 — 有证据的种子知识库：** 至少 80 张高质量卡片，覆盖不少于：30 单品、10 结构、10 材质/纹样、10 风格、10 时代/地域、10 Look/场景；尽量覆盖不同性别呈现与地域文化，不追逐数量。历史/文化事实必须逐条可追溯，不足目标则报告差距，不得虚填。

**P2 — 决策闭环：** 提供 `scripts/query.py`、推荐逻辑与 3 种可复制模板（角色、静态生图、视频），完成至少 15 个剧情场景测试，包括：历史准确 vs 艺术化、现代现实主义、阶层变化、舞蹈动作、雨夜湿衣、冷暖光对比、同角色多场连续性、低预算替代等。每例输出证据关联与解释性推荐。

**P3 — 扩充与集成（资源允许才做）：** 优先扩充高价值薄弱分支，目标 250+ 个有来源或明确标注设计推断的有效卡片；提供 `skills/costume-director/SKILL.md` 或同等 DSH 检索调用指南，非必需时不引入远程服务或复杂数据库。

## 6. 造型推荐原则
输入 schema：角色/职业/经济状态/时代与地理/具体场景/天气/动作/人物弧线/视觉风格/摄影与光线/预算/风格严格度/生成工具。
- **硬约束**：年代文化可行性（如要求史实）、天气保护、安全/行动自由、现场制作限制、伦理/版权等。
- **软评分**（可配置，合计100）：年代文化25，角色身份15，环境气候15，美术风格15，动作可行性10，剧情弧线10，摄影与一致性10。
- 给出 A（首选）、B（明确不同的次选）、C（预算或美术替代）各一套：单品 ID / 颜色 / 材质 / 结构 / 原因 / 风险 / 数据证据 / 提示词。
- 当历史准确性与视觉表现冲突时，明确区分 `historical` / `inspired` / `fictional` 三种模式。
- 绝不基于国籍、性别或职业刻板印象直接判断人物性格；任何心理意义为导演解释，不作为服装史事实。

## 7. 稳定输出格式
```
角色与剧情理解（区分已知/假设）
不可违反的约束
候选造型 A/B/C（Look ID、单品链接、配色与材质、适合原因、风险）
最终推荐 + 解释性评分
生图 Prompt（英文）
视频 Prompt（英文；镜头运动、动作、布料动态与服装锁定）
连续性检查点
来源 ID 与实际网页链接；证据不足处标记 uncertainty
```

## 8. 自动验收条件
- Obsidian 本地打开 Vault，笔记能显示并通过 `[[wikilinks]]` 跳转。
- 0 个 YAML 解析错误；0 个重复 ID；0 个坏的内部链接（允许人工记录例外但不得假装通过）。
- 所有历史/文化的 verified 卡片均有真实来源 ID；不含虚构链接或未经确认的图像授权。
- 至少 15 个剧情测试，需记录实际输入、输出、选择理由和失败案例；不能只是写“测试通过”。
- 至少有一个完整“多场次服装连续性”案例；同一 Look 的固定属性在不同提示词中不自相矛盾。
- 形成 `reports/STATUS.md`、`reports/COVERAGE.md`、`reports/QA.md` 与 `reports/SOURCES.csv`；清楚区分 PASS、PARTIAL、BLOCKED、NOT_TESTED。
- 当前轮次完成时总结：实际新增笔记数量、来源数量、脚本与用法、用户可打开的目录、未完成工作、下一轮最有价值的行动。

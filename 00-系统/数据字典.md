# 数据字典（P0 正式版）

本文件定义 Costume Director Knowledge System 的卡片类型、ID、字段、允许值与证据规则。所有卡片必须遵守本文件；`00-系统/卡片模板.md` 是本文件的配套模板。字段值以本文件为准，正文写作规范见第 9 节。

> 核心原则：Knowledge 层与 Inference 层分离。史实、术语、馆藏等可核验事实标 `verified` 并挂真实来源；设计判断标 `interpretive`；仅为格式演示的标 `example`；无法核验的标 `unverified`。**任何情况下不得伪造馆藏编号、作者、年代或 URL。**

## 1. 文件规范

| 项 | 规定 |
|---|---|
| 编码 | UTF-8（无 BOM），换行 LF |
| 格式 | Markdown + 扁平 YAML frontmatter，`---` 包围，文件第一行开始 |
| 嵌套 | **禁止**嵌套对象/嵌套列表；所有 frontmatter 值必须是一层标量或标量列表 |
| 列表 | YAML 行内数组 `[a, b]` 或块列表；空列表写 `[]`，不写 `null` |
| 布尔 | `true` / `false`（小写） |
| 日期 | `YYYY-MM-DD`（ISO 8601），例如 `date_accessed: 2026-11-04` |
| 数值 | 纯数字，不带单位；单位写入正文或 `note` |
| 字符串 | 含 `:`、`#`、`[]`、`{}` 等字符时必须加引号或用块标量 |
| 文件名 | `ID-中文名.md`，ID 与正文 `id` 完全一致；禁止空格（用 `-`）、`/`、`:` |
| 内部链接 | Obsidian 双链写法（ID-中文名） 或 双链写法（ID-中文名 或带显示文字），目标文件必须存在 |
| 兼容性 | 不依赖第三方 Obsidian 插件；不写 Dataview/Templater 专有语法作为必需字段 |

## 2. type 枚举与 ID 方案

| type | 含义 | ID 前缀 | ID 示例 | 所在目录 |
|---|---|---|---|---|
| `garment` | 物理单品（可穿戴的服装主体） | `GAR-` | `GAR-0001` | `01-服装单品/<子类>/` |
| `garment_part` | 结构细节/局部构造（领、袖、门襟、褶、闭合等） | `STR-` | `STR-0001` | `02-结构细节/` |
| `material` | 材料/织造/工艺属性 | `MAT-` | `MAT-0001` | `03-材质纹样/材料/` |
| `pattern` | 纹样/印花/图案 | `MAT-` | `MAT-0021` | `03-材质纹样/纹样/` |
| `style` | 审美/历史/亚文化/职业/电影类型/虚构风格 | `STY-` | `STY-0001` | `05-风格体系/` |
| `period_region` | 年代 + 地域/文化语境 | `PRD-` | `PRD-0001` | `06-时代地域/` |
| `look` | 一套具体搭配（可拆到 GAR/STR/MAT） | `LOOK-` | `LOOK-0001` | `09-造型组合/` |
| `scene` | 剧本场次/情境约束 | `SCN-` | `SCN-0001` | `07-剧情场景/` |
| `source` | 来源登记卡 | `SRC-` | `SRC-0100` | `04-来源/` |
| `rule` | 系统规则/决策规则/制作规则 | `RUL-` | `RUL-0001` | `00-系统/规则/` |

ID 规则：
- 格式 `前缀-四位数字`，全局唯一，只增不改；编号不复用、不回收。
- `example` 卡片使用 `前缀-EXAMPLE-三位数字`（如 `GAR-EXAMPLE-001`），与正式编号空间隔离。
- 来源卡编号段位：`SRC-0001..0099` 归来源包（researcher）；`SRC-0100..0149` 归 P1 单品/结构/材质卡自建来源；`SRC-0150..0199` 归 P1 风格/时代/Look 卡自建来源；`SRC-0200..0299` 归 P3/P4 缺口补卡自建来源（如 1930 年代上海组）；`SRC-0400..0449` 归 P3 知识扩展补卡自建来源（职业服/雨具/1940–70s/16 世纪与非西方组）；`SRC-0450..0479` 归 P3.3 补卡自建来源（莫卧儿 jama/paijama、哀悼珠宝）；`SRC-0480..0519` 归 P3.5 麦克白 analogue 补卡自建来源（中世纪/早期近代 tunic、cloak、hose、chemise、kirtle、belt、boots、dagger）；`SRC-0520..0529` 归 P4-2 结构分类扩展自建来源（FreeSewing 制版文档、V&A 结构/配饰对象）。超段位需在 `reports/` 登记。
- 同一物理对象的不同"卡版本"（如普通版/湿衣版）不另立 ID，用正文 `状态` 小节描述。

## 3. 必填字段

字段要求按卡片类型分两组：所有类型共用的基础字段，以及内容类型（非 source）的通用字段。**`type=source` 的来源卡只适用 §3.1 + §4.9**，不要求 §3.2 的服装导向通用字段。

### 3.1 所有类型必备（含 source）

| 字段 | 类型 | 必填 | 允许值/说明 |
|---|---|---|---|
| `id` | string | 是 | 见第 2 节 |
| `type` | enum | 是 | 见第 2 节 |
| `name_zh` | string | 是 | 规范中文名；有通行译名时用通行译名 |
| `name_en` | string | 是 | 英文规范名，小写优先（专有名词除外） |
| `evidence_status` | enum | 是 | `verified` / `interpretive` / `example` / `unverified`（source 卡的判定见 §7） |
| `review_status` | enum | 是 | `draft` / `reviewed` / `needs_review` |
| `license_status` | enum | 是 | `cc0` / `cc_by` / `other_permission` / `link_only` / `not_applicable` / `unknown` |
| `tags` | list[string] | 是 | Obsidian 检索标签，建议 `costume` + 层级标签 |

### 3.2 内容类型额外必备

适用于 `garment` `garment_part` `material` `pattern` `style` `period_region` `look` `scene` `rule`（共 9 类）；**`source` 不在此列**。

| 字段 | 类型 | 必填 | 允许值/说明 |
|---|---|---|---|
| `category` | enum | 是 | 类型级类别，见第 6 节 |
| `subcategory` | string | 是 | 受控词表前缀 + 具体词，见第 6 节；未知写 `unknown` |
| `aliases` | list[string] | 是 | 别名/外文名/行业俗称；无则 `[]` |
| `periods` | list[string] | 是 | 年代区间，如 `[late_19th_century]`；未知 `[]` |
| `regions` | list[string] | 是 | 地域/文化，如 `[japan]`；未知 `[]` |
| `style_tags` | list[string] | 是 | 风格标签，引用 STY ID 或自由标签；无则 `[]` |
| `colors` | list[string] | 是 | 主色/允许色，如 `[indigo, white]` |
| `materials` | list[string] | 是 | 材料，如 `[silk, cotton]` |
| `source_ids` | list[string] | 是 | 已存在的 `SRC-` ID；`verified` 内容卡须 ≥1；`interpretive`/`example` 可为 `[]` |

> **v1.2 可选字段**：内容类型可在 §3.2 必填字段之外，按需追加 [[数据字典-v1.2-扩展]] 中的可选字段；不填写不影响合法性。

> **来源卡豁免说明**：`type=source` 不要求 `category`、`subcategory`、`aliases`、`periods`、`regions`、`style_tags`、`colors`、`materials`、`source_ids`。现有 142 张来源卡中，82 张保留了这些字段的空值/占位（如 `category: source`、空列表），其余 60 张完全没有这些字段；**两种写法都合法**，校验器不得对 source 卡检查或要求这些字段。来源卡自身的必填字段与正文要求见 §4.9。

**来源卡正文（不适用 §9 的 8 节要求）**：来源卡正文允许两种既有写法，校验器不得强制 8 节。
- 研究型（现有 60 张）：`## 可支撑事实（verified）`、`## 验证记录`、`## 使用限制`、`## 可配合的主题`；
- 内容型（现有 82 张）：沿用内容卡标题但改写为来源说明（如 `## 定义` 写来源性质、`## 来源链接` 列 URL、`## 视觉辨识` 写"不适用"）。

最低正文要求（不依赖固定标题）：必须写明 (1) 可支撑事实/断言范围；(2) 实际核验记录（命令、HTTP 状态、日期）；(3) 不能支撑的断言或使用限制。`## 相关卡片` 可选。
校验器建议规则：`type=source` 时检查 `url`/`publisher`/`date_accessed`/`rights_statement`/`source_kind`/`note` 非空；正文含 `## 可支撑事实` 或 `## 定义` 之一，且含 `## 验证记录` 或 `## 来源链接` 之一；不再检查 8 节。

## 5. 分类维度 A–F

| 维度 | 含义 | 承载类型 | 典型字段 |
|---|---|---|---|
| **A 物理单品** | 可穿戴的服装/鞋/配饰主体 | `garment` | category, subcategory, silhouette, fit, materials |
| **B 结构与形态** | 领/肩/袖/门襟/口袋/腰线/褶裥/衩/缝/闭合/长度/层搭 | `garment_part` | part_family, structural_notes |
| **C 属性** | 廓形、版型、材料、重量、垂坠、反光/透明/弹性、颜色、纹样、磨损、动态、布光 | `material` `pattern` + garment 的 C 类字段 | materials, colors, movement_notes, lighting_notes |
| **D 风格** | 历史风格/艺术运动/亚文化/职业制服/电影类型/虚构世界观（多对多标签） | `style` | style_family, style_tags |
| **E 时空与剧情** | 年代、地域、气候、礼仪、阶层、身份、人物弧线、场景行为、摄影、预算 | `period_region` `scene` | period_label, region_label, social_context |
| **F Look 与连续性** | 具体搭配、场次映射、破损/污渍/湿度/配饰状态 | `look` `scene` | look_items, continuity_lock, scene_* |

硬规则：
- 不得把"西装（单品）""极简主义（风格）""丝绸（材料）""1930 年代（年代）"放在同一层级或同一类型卡中。
- 一张 `style` 卡不得替代具体 `garment` 卡；一个 `garment` 卡不得仅凭风格词定义。
- `look` 卡必须能拆解到具体单品/结构/材料 ID；无法拆解时标 `example` 或 `interpretive`。
- `period_region` 卡不得给出无来源的伪精确年代。

| 字段 | 值 | 判定规则 |
|---|---|---|
| `evidence_status` | `verified` | 内容卡：至少 1 个 `SRC-` 卡，且该来源 URL 经 `curl -sS -m 10 -L` 实测 HTTP 200、页面内容直接支持卡片中的具体事实；来源卡：其自身 `url` 经实测 HTTP 200 且 `note` 记录实测状态（**不要求 `source_ids`**） |
| | `interpretive` | 基于 verified 事实作出的设计/风格/剧情推断；正文必须写明"推断"及依据卡 |
| | `example` | 仅为模板/演示/虚构示例，不作为史实引用 |
| | `unverified` | 有来源线索但未实测，或来源不支持断言；不得挂 verified 所需的 `source_ids` 作为唯一依据 |
| `license_status` | `cc0` | 明确 CC0/公共领域（注意：Met 数据与 Met 图片权利不同，需逐项核验） |
| | `cc_by` | 明确 CC BY（记录版本与署名要求） |
| | `other_permission` | 有明确但非 CC 的授权 |
| | `link_only` | 版权不明：只存链接，不复制图片/全文 |
| | `not_applicable` | 内部原创卡/规则/示例，无外部版权对象 |
| | `unknown` | 尚未核验 |
| `review_status` | `draft` | Agent 生成，未人工复核 |
| | `reviewed` | 已完成来源抽查与字段校验 |
| | `needs_review` | 已知可疑/待人工判断 |

verified 卡的最低证据要求（逐条检查）：
1. **内容卡**：`source_ids` 非空且每个 ID 在 `04-来源/` 中存在；
2. **来源卡**：`url` 与 `date_accessed` 非空，`note` 写入实测命令、HTTP 状态与访问日期；`source_ids` 可为 `[]` 或省略；
3. 实测命令、HTTP 状态、访问日期写入来源卡 `note`；
4. 卡片正文的每个史实断言可在来源页找到对应表述（允许合理转述，不允许扩写）；
5. 不得引用未核验的二手转述（如无来源 Pinterest、营销文案）作为 verified 依据。

## 8. 命名与本文件位置规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 卡片文件名 | `ID-中文名.md`，中文名取 `name_zh` | `GAR-0001-和服.md` |
| 来源卡文件名 | `SRC-编号-机构简称-主题.md` | `SRC-0100-Met-日本江户和服.md` |
| 规则卡 | `RUL-编号-主题.md` | `RUL-0001-来源核验规则.md` |
| wikilink | 链接到完整文件名（不含 `.md`） | `[[GAR-0001-和服]]` |
| 目录 | 按类型分目录，单品按 category 分子目录 | `01-服装单品/上装/` |
| 标签 | 小写、下划线分隔、不含空格 | `costume` `garment` `region_japan` |

## 9. 正文结构规范

**内容类型卡片**（`garment` `garment_part` `material` `pattern` `style` `period_region` `look` `scene` `rule`）正文必须包含以下二级标题（允许顺序微调，但不得缺项）。**来源卡（`type=source`）不适用本节**，其正文要求见 §4.9：

1. `## 定义` —— 一句话定义 + 1–2 句说明。
2. `## 结构要点` —— 结构/工艺/部件/比例要点（结构卡、材质卡可改为工艺要点）。
3. `## 视觉辨识` —— 在画面中如何一眼识别，含正面/侧面/背面/细节差异。
4. `## 适用条件` —— 年代、地域、阶层、场合、气候、动作、艺术风格等。
5. `## 不适用条件` —— 容易穿帮/违背年代/不适合动作或预算的情形。
6. `## 提示词短语` —— 英文提示词片段（可复制），并给出中文造型说明。
7. `## 来源链接` —— 逐条列出 `SRC-` ID + 实际 URL + 该来源支撑的具体断言。
8. `## 相关卡片` —— Obsidian 双链到 3–8 个相关卡片（同层/上下层均可）。

可选标题：`## 历史脉络`（仅 verified 时写实）、`## 连续性注意`、`## 设计推断`（与史实分开）、`## 常见误用`。

## 10. 校验规则（供 scripts/validate.py 对齐）

1. 每张卡片 frontmatter 可被 PyYAML `safe_load` 解析，且为 dict。
2. 必填字段：所有类型检查 §3.1；内容类型再加 §3.2；`source` 类型按 §4.9 检查 `url`/`publisher`/`date_accessed`/`rights_statement`/`source_kind`/`note`。`type` 在枚举内；内容类型 `category` 在枚举内；`id` 前缀与 type 匹配。
3. 全库 `id` 唯一；文件名与 `id` 一致。
4. `source_ids` 解析检查**仅对内容卡**：每个 ID 在 `04-来源/` 有对应卡片且来源卡 `url` 非空。source 卡 `source_ids` 可为 `[]` 或省略。
5. `evidence_status == verified` ⇒ 内容卡 `source_ids` 至少 1 条；来源卡 ⇒ `url` 非空且 `note` 含实测记录（不要求 `source_ids`）。
6. `verified` 内容卡事实在正文 `## 来源链接` 有对应 SRC；来源卡核验记录见其正文（`## 验证记录` 或 `## 来源链接`）。
7. 正文 8 个必需标题**只对内容类型**检查；来源卡按 §4.9 的宽松规则检查，不得要求 8 节。
8. 所有 Obsidian 双链目标存在；坏链为 0（人工例外需在 `reports/QA.md` 记录）。
9. `license_status` 在枚举内；图片一律 `link_only` 或明确授权，不在 Vault 内嵌未授权图片。
10. 无重复 ID、无伪精确年代、无无来源的馆藏编号。
11. 来源卡不检查 `category`/`subcategory`/`aliases`/`periods`/`regions`/`style_tags`/`colors`/`materials`（82 张有占位、60 张没有，均合法）。

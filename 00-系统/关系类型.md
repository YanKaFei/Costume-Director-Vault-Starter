# 关系类型（P5-A 类型化关系 Schema）

- 版本：v3（2026-11-05，task-61/65/77；P5-B 语义纠错 + P5-C style_interpretation/design 关系规则）
- 性质：**只读候选模型**。本文件只定义关系、生成规则与迁移/审核分层；不修改任何卡片正文或事实。
- 候选文件：`11-验收/P5/RELATION-CANDIDATES.csv`（高置信=`migration_ready`，中/低=`review_queue`）
- 导航页：`00-系统/MOC/`；说明报告：`reports/P5-MOC.md`
- 源白名单（权威）：`11-验收/P5/source-audit.csv`（researcher/task-62；列 `source_id`、`migration_class` 等）。`whitelist_connected`/`whitelist_independent` 可支撑关系；`action_needs_citation`/`action_should_connect` 只进审核；`blacklist_duplicate`（SRC-0157/SRC-0163/SRC-0175）不得作为新关系目标。`reports/SOURCES.csv` 为登记对账快照。不新建来源、不联网补证、不编造目标 ID。

## 1. 原则

1. **只用结构化字段**：关系必须来自 frontmatter 的 ID 列表/枚举字段（`look_items`、`look_scene`、`key_garments`、`source_ids`、`style_tags` 中的 `STY-xxxx`、`category/subcategory` 等）；不得仅凭颜色/地区/风格词（黑色/欧洲/古典）推断历史事实。
2. **方向显式**：每条关系有 subject → object；双向/对称关系在 `direction` 标注 `symmetric`，仍以固定 subject/object 存档。
3. **证据随关系传播**：`evidence = 最弱端点证据`（example < interpretive < verified）；设计共现关系不能获得 `verified` 史实含义。
4. **置信分层**：
   - `high`：显式 ID 列表字段直接产生 + 两端 `verified`/非 `deprecated` + `source_ids` 非空 + 无歧义映射；可进入迁移工具。
   - `medium`：显式字段但一端 `interpretive`/`draft`；或设计共现（`may_have_part`/`ensemble_with` 设计上最高 medium）。
   - `low`：任一端 `example`；别名/族级/多义映射；目标是 `deprecated` 卡。中/低一律进审核队列。
5. **不伪造**：无结构化字段支持的配对不生成（宁缺毋滥）；不把 `may_have_part` 说成 `has_part`，不把 `context_includes` 说成“该单品被证实穿于该年代”。
6. **不修改卡片**：P5-A 只产出候选/MOC；如需迁移关系入卡，必须由另任务按本 schema 写入，高置信才可写，且不改变既有必填字段与正文事实。

## 2. 关系类型表

| relation_type | subject → object | 来源字段（唯一允许） | 语义/证据含义 | 最高置信 |
|---|---|---|---|---|
| `appears_in_look` | look → garment / garment_part / material / pattern | `LOOK.look_items` | 该 LOOK 的已策展组成；组合本身是设计/解释，不自动是史实 | high（LOOK+item 均 verified 且 source_ids 非空） |
| `look_appears_in_scene` | look → scene | `LOOK.look_scene` | LOOK 被明确用于该场景 | high（LOOK+SCN 均 verified） |
| `context_includes` | period_region → garment / garment_part | `PRD.key_garments` + `PRD.source_ids` | 时代/地域语境卡明确列出的典型单品；**语境级**证据，不等于逐单品历史证明 | high（PRD verified + target verified + PRD source_ids） |
| `in_style` | garment / garment_part / look → style | subject `style_tags` 中的精确 `STY-xxxx` | 风格归属；精确 ID 才是结构化，自由 tag 仅为候选线索 | high（精确 STY ID + STY verified + subject verified） |
| `style_interpretation` | look / garment / garment_part → style（`STY-xxxx`）；或 style → look（`LOOK-xxxx`，curated design×LOOK interpretation） | subject `style_tags` 精确 `STY-xxxx`（→STY）；或显式 curated `R-CURATED-DESIGN` 引用（style→LOOK） | **设计解释关系**：说明为何把该 LOOK/单品解读为某风格，或某风格如何被解读到 LOOK；不是“当时风格事实”；`factual=false`、`design_only=true` | **medium（固定；禁止 high）** |
| `uses_material` | content → material | subject `materials` token 与 MAT 卡 `materials`/`fiber_content` 的**精确 token** | 材料族/纤维级候选；token 不是 canonical ID，故需人工确认 | medium（唯一映射、两端 verified；多义→low） |
| `may_have_part` | garment → garment_part | 同一 `LOOK.look_items` 内共现（无 `has_part` 字段） | **仅为候选**：共现不等于结构上的“有该部件”；供审核后建 `has_part` | medium（设计共现上限） |
| `ensemble_with` | garment → footwear/accessory/headwear/carried_prop | 同一 `LOOK.look_items` 内共现 | 搭配/组合候选，不是历史搭配证明 | medium（设计共现上限） |
| `claim_supported_by` | content → source | subject `source_ids`（目标须为 `type=source`） | 卡片断言由来源卡支撑；证据强度取两者最弱；规则 `R-SOURCE-IDS` | high（claim verified + source verified + source 在 whitelist） |

### 2.1 五级证据分类（P5-B，所有关系必须标注）

| evidence_level | 定义 | 典型关系 | Agent 使用边界 |
|---|---|---|---|
| `direct_evidence` | 来源直接陈述该关系，来源年代/地域范围覆盖断言 | `claim_supported_by`（scope 匹配）、`context_includes` 的 compatible 语境 | 可用于历史判断；必须仍是 high/verified 且 scope 匹配 |
| `indirect_interpretation` | 来源只支持语境/类比/材料族（token），关系为解释性延伸 | `context_includes`（语境级）、`uses_material` token、`appears_in_look` 设计组合 | 可用于解释/建议，必须标注“语境/候选”，不得说成逐件史实 |
| `later_influence` | 来源或实例晚于目标年代（现代复刻/后世设计） | 用 2014 实例解释通用风衣历史（GAR-0045→SRC-0405） | **不得**用于证明早期/通用历史；只能作“实例/影响” |
| `creative_inference` | 设计/策展推断：LOOK 组合、`ensemble_with`、`may_have_part`、风格标签/解读 | `appears_in_look`、`ensemble_with`、`may_have_part`、`in_style`/`style_interpretation` 设计层 | 只能作设计建议；不得进入历史/结构事实 |
| `unsupported_conflict` | 年代/地域/类型/语义冲突（例：1950s 语境→1960s+单品；拜占庭→16–19c 编带；物性卡当材料；codpiece→collar） | 见 `reports/P5B-RELATION-CORRECTIONS.csv` | 从正式 `relations`/`key_garments` 移除或标 rejected；**禁止参与历史判断** |

`evidence_level` 是比 `evidence`/`confidence` 更上层的语义判定；迁移/Agent 必须同时满足 level 与 confidence 门槛。

**不支持的（诚实缺口，不生成）**：`character_wears_look`（无结构化 character ID；`scene_character`/`look_role` 是自由文本）；`has_part`（无 `part_ids` 字段）；`worn_in_period` 的逐单品史实断言（`periods` 字段只用于导航/候选，历史断言必须另有人类审核的证据）。

## 3. 候选记录字段（CSV 规范）

`11-验收/P5/RELATION-CANDIDATES.csv` 列：

`relation_id,relation_type,direction,subject_id,subject_type,object_id,object_type,evidence,confidence,factual,design_only,rationale,source_ids,rule_id,review_status`

- `relation_id`：`REL-0001` 顺序稳定；同 `(relation_type,subject_id,object_id)` 去重。
- `direction`：CSV 用 `subject_to_object` / `symmetric`；卡片迁移字符串可写 `outgoing`（等价于 subject_to_object），见 §4/engineer task-60 既有格式。
- `evidence`：`verified` / `interpretive` / `example`（最弱端点）。
- `confidence`：`high` / `medium` / `low`。
- `rationale`：结构化来源 + 为什么是该置信（不写关键词推断）。
- `source_ids`：分号分隔且都存在于 `04-来源/`；无则留空并降级（high 不允许空）。
- `rule_id`：`R-LOOK-ITEMS` / `R-LOOK-SCENE` / `R-PRD-KEY-GARMENTS` / `R-STY-EXACT` / `R-MAT-TOKEN` / `R-LOOK-PART-COOCCUR` / `R-LOOK-ENSEMBLE` / `R-SOURCE-IDS`（engineer/task-60 已用此名迁移 source 关系；`R-CARD-SOURCE` 为旧别名，不再用于新行）。
- `review_status`：`migration_ready`（high，可被迁移工具消费）或 `review_queue`（medium/low，人工审核后才可迁移）。
- `factual`：`true` / `false`；只有 `direct_evidence` 的事实关系可为 `true`。`style_interpretation`、`may_have_part`、`ensemble_with`、`uses_material`、`in_style` 的设计层必须 `false`。
- `design_only`：`true` / `false`；`style_interpretation` 固定 `true`；`may_have_part`/`ensemble_with`/`uses_material`/`in_style` 设计层标 `true`。
- `style_interpretation` 的 CSV 行固定 `evidence=interpretive; confidence=medium; factual=false; design_only=true; review_status=review_queue`；迁移工具**不得**将其写入 `migration_ready`/正式历史关系。

## 4. 卡片内表示（若后续迁移任务写入）

v1.1 规定 frontmatter 只允许扁平标量与标量列表，**禁止嵌套 map**。因此若迁移，使用扁平字符串列表，不写对象数组：

```yaml
relations:
  - "target=STR-0009; type=may_have_part; direction=subject_to_object; evidence=interpretive; confidence=medium; source_ids=SRC-0150; rule=R-LOOK-PART-COOCCUR"
  # 已迁移的 source 关系（engineer/task-60 既有格式）：
  - "target=SRC-0103; type=claim_supported_by; direction=outgoing; evidence=verified; confidence=high; source_ids=SRC-0103; rule=R-SOURCE-IDS"
```

- 仅 `high` 可写入卡片；`medium/low` 留在 `11-验收/P5/REVIEW-QUEUE.csv`（审核后可升级）。
- 卡片正文如需人读，可在 `## 关系` 小节列高置信关系；正文不改变既有 8 节结构/事实。
- 不自动改任何卡片：P5-A 仅交付候选；迁移工具由工程师任务消费 CSV 的 `migration_ready` 行。

## 5. 规则与置信判定（summary）

| rule_id | 生成条件 | 证据 | 置信 |
|---|---|---|---|
| `R-LOOK-ITEMS` | `LOOK.look_items` 中存在的合法 ID | LOOK 与 item 最弱 | high/medium（含 interpretive/example 则降） |
| `R-LOOK-SCENE` | `LOOK.look_scene` 中存在的合法 SCN ID | LOOK 与 SCN 最弱 | high/medium |
| `R-PRD-KEY-GARMENTS` | `PRD.key_garments` 中存在的合法内容 ID | PRD 与 target 最弱；source_ids=PRD.source_ids | high/medium（无 PRD source_ids→不得 high） |
| `R-STY-EXACT` | subject `style_tags` 精确包含 `STY-xxxx`（且 STY 卡存在） | STY 与 subject 最弱 | high/medium |
| `R-STYLE-INTERPRETATION` | 人工/显式 curated 的 LOOK/garment→STY 设计解读；无通用自动规则 | 仅 `interpretive` | **medium（固定，不可 high）** |
| `R-CURATED-DESIGN` | 显式 curated 的 style→LOOK 设计解读（engineer/task-76；`STY-0011..0015` 使用） | 仅 `interpretive` | **medium（固定，不可 high）** |
| `R-MAT-TOKEN` | subject `materials` token 精确命中 MAT `materials`/`fiber_content` | MAT 与 subject 最弱 | medium（唯一）/low（多义） |
| `R-LOOK-PART-COOCCUR` | 同一 LOOK 同时含 garment 与 garment_part | LOOK 最弱 | medium（example→low） |
| `R-LOOK-ENSEMBLE` | 同一 LOOK 同时含 clothing 与 footwear/accessory/headwear/carried_prop | LOOK 最弱 | medium（example→low） |
| `R-SOURCE-IDS` | content `source_ids` → 存在的 source 卡（白名单内才 high） | claim 与 source 最弱 | high/medium/low |

## 6. 冲突与去重

- 同一 `(relation_type, subject, object)` 只保留一条；若多规则命中，取最高置信并合并 `source_ids`（`rationale` 注明规则）。
- `deprecated: 'true'` 的卡不作为 subject/object；旧 ID 只保留 redirect，不生成关系。
- 同一对卡片可存在不同 `relation_type`（如 LOOK→STR 的 `appears_in_look` + garment→STR 的 `may_have_part`），`relation_id` 不同。
- 若结构化字段引用不存在的 ID：不生成关系，记入报告冲突/缺口（不在本 CSV 造假行）。

## 7. 与 MOC 的关系

`00-系统/MOC/` 只做导航（目录/分类/链到卡片），不把候选关系当事实展示；页面上标注“导航，非事实断言；关系候选见 CSV，需审核”。不为连通率硬连。

## 7.1 设计关系规则（P5-C/task-77）

以下关系属于**设计/解释层**，可在审核队列中为 `medium`，但不得升格为 `high` 事实、不得进入历史判断：

| relation_type | 最高置信 | factual | Agent 使用 |
|---|---|---|---|
| `style_interpretation` | medium（固定） | false | 仅作“为什么这样解读风格”的设计说明；不得写成“当时风格/史实”；不得进入历史理由 |
| `uses_material` | medium | false（token/族级） | 材料族候选；需 canonical material 后才可作材料事实 |
| `may_have_part` | medium | false | 共现候选；**永不是** `has_part`；不得进结构事实 |
| `ensemble_with` | medium | false | LOOK 搭配/策展候选；不是历史搭配 |
| `in_style` | high 仅限精确 STY ID + 来源（v2 保留） | false（历史层） | 可作风格标签/设计参考；不得当“史实风格证据” |

- `style_interpretation` 的 subject→object 允许：look→STY、garment/garment_part→STY；也允许 curated 的 style→LOOK（`R-CURATED-DESIGN`，如“此风格被解读到该 LOOK”）与对 `LOOK` 的设计解释；必须在 `rationale` 写明是设计解释，不是来源断言。
- 所有 design 关系不得进入 `migration_ready`；若迁移工具只消费 high，其天然被排除；若人工提升为 factual，必须有直接来源并走重新审核（不自动提升）。
- **Agent 过滤**：回答历史问题前先过滤 `factual=false` 或 `design_only=true` 的关系；`style_interpretation` 只能出现在设计/风格说明；不得作为年代、地域、穿着事实或“某风格诞生”的依据。
- **可见性（medium design relation）**：medium 的 `uses_material`/`may_have_part`/`ensemble_with`/`style_interpretation` 必须在卡片正文有可见 `[[target]]` 或等价的 review marker；没有 visible marker 视为 `review_queue`，**不计入强证据/覆盖**（例：STR-0029→MAT-0001 的 medium uses_material 仅有 token 来源、正文无 MAT-0001 链接 → 保留 review，由卡片 owner 补 marker 或移除）。high factual 关系（claim_supported_by/context_includes）仍需可见链接。

## 10. P5-B 纠错后规则（v2，2026-11-05）

1. **`uses_material` 排除属性/纹样卡**：`MAT-0012 织物组织`、`MAT-0013 克重与垂坠` 是 material_property，`MAT-0005/0006/0007` 是 pattern；不得作为 `uses_material` 目标。只允许真实 material/fiber/trim/metal 卡；token 映射最高 medium，high 一律禁止。GAR-0020/PRD-0002 的 MAT-0001 关系已降 medium/R-MAT-TOKEN，仍为 review。
2. **`may_have_part` 永不是结构事实**：只允许 `review_queue`，不得写 `has_part`，不得迁移；语义不通的配对（例 GAR-0013 codpiece → STR-0001 Medici collar）直接 rejected。`ensemble_with` 同理（设计搭配，最多 medium）。
3. **`context_includes` 只做语境级间接解释**：目标 `periods/regions` 必须与 PRD 兼容（区间重叠）；宏观语境不得写成逐单品史实。明确冲突的 key_garments 必须移除或替换，并在 `reports/P5B-RELATION-CORRECTIONS.csv` 记录 old/new/evidence。
4. **`claim_supported_by` 必须检查来源覆盖范围**：来源年代/主题不覆盖断言时不得 high；后世/实例来源标 `later_influence` 并降 medium（GAR-0045→SRC-0405）；背景来源不能替代主证据（GAR-0033 的 SRC-0155 已移除，保留 SRC-0204）。
5. **`in_style` 是创作推断**：exact STY ID 只是风格标签，不是史实风格证据；不得用于历史判断或迁移为“历史风格事实”。
6. **Agent 规则**：`direct_evidence` 才可用于历史判断；`indirect_interpretation` 必须 hedge（“语境/候选/可能”）；`later_influence` 不得证明早期历史；`creative_inference` 只作设计建议；`unsupported_conflict`/rejected 一律排除，不得进入推荐的历史理由。
7. **修正记录**：所有关系/ key_garments 修正写入 `reports/P5B-RELATION-CORRECTIONS.csv`（`card_id,old,new,evidence,action,status` + `audit_id,evidence_level,rationale,source_ids,file`）；不删除卡片、不改来源事实；无依据不替换，宁缺毋滥。
8. **验证**：P5-B 后 `validate.py` PASS 400/400、0 errors/0 warnings；关系候选 CSV 由 P5-A 生成，不在 P5-B 写范围；下游应过滤 `reports/P5B-RELATION-CORRECTIONS.csv` 的 `status=rejected` 与按本规则重判 `review_queue`。

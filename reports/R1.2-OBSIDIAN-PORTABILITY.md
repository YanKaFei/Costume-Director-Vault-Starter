# R1.2-A — Portable Obsidian config + isolated reproduction

- Date: 2026-11-05
- Scope: `config/obsidian/`, `docs/OBSIDIAN-SETUP.md`,
  `docs/OBSIDIAN-MIGRATION.md`, `scripts/obsidian_config.py`,
  `tests/test_obsidian_config.py`; live `.obsidian` untouched except by explicit
  `--apply`.
- Obsidian version audited: **1.14.5**.

## 1. Current state / storage

- `userIgnoreFilters` is stored in `.obsidian/app.json`.
- `.obsidian/` is in `.gitignore`; therefore the live config is machine-specific
  and not portable by git. Portable source is the templates in `config/obsidian/`.
- Current production `app.json` already has the recommended filters; a dry-run
  reports `changed: false`.
- `userIgnoreFilters` is Obsidian's global excluded-files setting: it affects graph,
  search, backlinks and quick-open. `graph.json` `search` is a temporary
  graph-only scope and is **not** the same thing; the template keeps it empty.
- Recommended scope is **488 knowledge nodes / 0 zero-degree / 1 component**;
  full-vault counts (audit/sandboxes) are intentionally excluded.

## 2. Templates

`config/obsidian/app.recommended.json` — only:
```json
{"userIgnoreFilters": ["11-验收/","reports/","projects/","docs/","tests/",
 "skills/",".dsh/","TASKS/","TASKS.md","AGENTS.md"]}
```

`config/obsidian/graph.recommended.json` — graph display/force keys only; no
`scale`, `close`, personal workspace, credentials or absolute paths.

## 3. Script behavior

`scripts/obsidian_config.py`:
- default **dry-run**, `--apply` required for writes;
- `--diff` shows app/graph differences;
- app merge: union recommended filters with current filters, all other user keys
  preserved;
- graph merge: only fill missing recommended keys, never overwrite existing user
  keys (scale/custom keys preserved);
- whole `.obsidian` backup before apply;
- idempotent;
- `--restore BACKUP` restores app/graph only, leaving themes/plugins/hotkeys/
  workspace untouched;
- `--scope-report` computes nodes/zero-degree/components with code links ignored;
- never writes themes/plugins/hotkeys/workspace/appearance.

## 4. Isolated-vault test

`tests/test_obsidian_config.py` creates a clean copy of the knowledge dirs
(`00-系统` … `10-提示词模板`) plus `.obsidian`, adds user-owned custom
keys/filter/theme/hotkeys/workspace, then runs the CLI.

Tests: **6/6 PASS**. Production dry-run: `changed: false`.

## 5. Risks / rollback / cross-device

- Risk: user expects a different ignore scope; `--diff` before apply, filters are
  additive (never silently removes user filters).
- Risk: graph template only fills missing keys; if the local graph is customized,
  it is preserved by design.
- Rollback: `python3 scripts/obsidian_config.py --restore /tmp/obsidian-config-backup-...`
  (backup path printed by apply).
- Cross-device: clone vault without `.obsidian`, run `--diff` then `--apply`;
  templates are tracked. Keep the backup until GUI inspection.
- GUI graph/backlink appearance remains a human visual check; this automation
  verifies config/scope only, not screenshots.

## 6. Limits

- 488/0/1 is the configured **knowledge scope**, not the full vault; sandboxes and
  audit evidence are deliberately excluded.
- Obsidian GUI behavior/version-specific rendering is not executed here; no GUI
  PASS is claimed.
- The script does not merge arbitrary plugin settings; it only owns app/graph keys
  described above.
